# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

TripTogether (package name `tripshare`): Next.js 16 / React 19 proof-of-concept where users organize or join trips. Two-person course project, demoed live. Live at https://share-trip-inky.vercel.app (Vercel Hobby, auto-deploys from `main`, region `fra1`). The user prefers answers in Romanian. Hosting must stay free: no Docker, VPS or workers. See `README.md` for setup, demo logins and zone owners.

## Next.js is not the one you know

Next 16.4 has breaking changes (see `AGENTS.md`). Read the relevant guide in `node_modules/next/dist/docs/` before writing Next-specific code. Example already in the repo: `src/proxy.ts` replaces `middleware.ts`.

## Commands

Package manager is pnpm (`packageManager` is pinned); Node 24 (`.nvmrc`).

- `pnpm dev` / `pnpm build` / `pnpm start`
- `pnpm lint` · `pnpm typecheck` (runs `next typegen` first, then `tsc --noEmit`)
- `pnpm test` (Vitest, `src/**/*.test.ts`, no DB: `@/db/client` is mocked) · `pnpm test:file src/lib/format.test.ts` for one file
- `pnpm e2e` (Playwright smoke in `e2e/`, serves the production build on :3100, so run `pnpm build` first; needs no DB or secrets)
- `pnpm check` = lint + typecheck + unit tests; the same gate runs locally (hooks) and in CI
- Database (Drizzle, uses `DIRECT_URL`): `pnpm db:generate` after editing `src/db/schema/*`, commit the new SQL in `drizzle/`; `pnpm db:migrate`; `pnpm db:check`; `pnpm db:studio`
- Scripts (read `.env.local` via `tsx --env-file`): `pnpm db:seed-admin`, `pnpm db:seed-demo`, `pnpm db:setup-storage`

Secrets live only in `.env.local`; `.env.example` lists every variable. `BETTER_AUTH_URL` must equal the deployed URL in production.

## Architecture

One Next.js app with route-group "zones" under `src/app/`: `(main)` landing, `(auth)` login/signup, `(organizer)`, `(joiner)` (placeholder, another developer builds it), `admin`, shared `feed`, plus `api/auth/[...all]` (Better Auth handler). Mutations are Server Actions in `src/app/actions/{auth,trips,admin}.ts`; there is no REST API besides the auth handler.

**Auth and authorization** (spans `src/lib/auth.ts`, `src/lib/session.ts`, `src/proxy.ts`):
- Better Auth with Drizzle adapter, `username` + `admin` plugins, email/password (min 10 chars, no email verification). `nextCookies()` must stay last in the plugins list so Server Actions can set cookies. Rate limiting is stored in the DB because in-memory does not work on serverless.
- One global role per account (`user` | `admin`). "Organizer"/"Joiner" are per-trip relationships (`trips.organizerId`, rows in `trip_members`), not roles.
- `src/proxy.ts` only redirects when there is no session cookie. It is NOT a security boundary: every admin page/action must call `requireAdmin()` / `assertAdmin()`, every user zone `requireUser()` (all in `src/lib/session.ts`).
- Server code connects to Postgres directly, which bypasses Supabase RLS, so ownership checks (e.g. "is this my trip") must be written in the action itself.
- Signup requires a profile photo, enforced in a Better Auth `databaseHooks.user.create.before` hook, not only in the form, because the public sign-up endpoint can be called directly.

**Database** (`src/db/`): `schema/auth.ts` is generated by Better Auth tooling, `trips.ts` and `trip-members.ts` are ours. `src/db/client.ts` throws at import if `DATABASE_URL` is missing (tests and CI builds need a dummy value). It uses the Supabase transaction pooler (port 6543) with `postgres.js` `prepare: false` and `max_pipeline: 1`; removing either makes concurrent queries hang. Migrations use the session pooler (`DIRECT_URL`, port 5432).

**Users created outside the sign-up flow:** `src/lib/user-service.ts` (`createCredentialUser`) inserts user + credential account in one transaction, hashing with Better Auth's own hasher. Used by the admin "create user" action and the seed scripts, so it must not import `server-only`.

**Photos:** `src/lib/storage.ts` uploads to a public Supabase Storage bucket using the server-only secret key. Type is detected from file signature (JPG/PNG), max 2 MB, generated file names. `next.config.ts` raises the Server Action body limit to 3 MB for this.

**UI:** shadcn/ui on Base UI (not Radix) in `src/components/ui`, Tailwind 4 via `@tailwindcss/turbopack` rules in `next.config.ts`, `src/data/{trips,users}.ts` (server-only) is the Drizzle query layer that pages call for reads. Cache Components is intentionally off.

## Rules for shared files

Edit your own zone; changes to shared files (`src/db/schema`, `src/lib/auth.ts`, `src/components/ui`, root layout) go in small PRs. The Joiner developer plugs into `FeedTripCard`'s `action` slot and adds `chats`/`messages` tables; keep `trip_members` and that slot stable.

## Workflow

- Features and behaviour changes run through the harness workflow (the `harness` skill), started by describing the change or with `/harness <ask>`: the planner's questions, your plan approval, tests first, implementation, verification, review, learnings, your final approval. Small fixes, docs and CSS: work directly.
- Commands (quiet output):
  - test: `pnpm test` · single file: `pnpm test:file <path>`
  - lint: `pnpm lint` · types: `pnpm typecheck`
  - full check, same as pre-commit and CI: `pnpm check`
  - end-to-end / run the app: `pnpm build && pnpm e2e` · `pnpm dev`
- Specs and plans: `specs/<slug>/`. Decisions: `docs/adr/`. Mistakes not to repeat: `docs/learnings.md`, read before planning.
- Roles: `.claude/agents/harness-*.md`. LEARN may refine them, with approval; it never loosens them or touches hooks, settings or CI.
- Agents never commit or push. A human does, after reviewing the change. Keep this file under 200 lines.
- Git: issue -> branch `<type>/<slug>` from `main` (any name but `main`) -> push branch -> PR (`Closes #n`) -> CI on GitHub -> squash merge on GitHub. Never work on `main`; full steps in `docs/git-workflow.md`.
- Release: PR into `main` -> CI (`.github/workflows/ci.yml`) must be green -> merge -> Vercel deploys; migrations in `drizzle/` are applied by `.github/workflows/migrate.yml` and must be backward compatible (add first, remove in a later release), because deploy and migration start together.

## MCP servers (`.mcp.json`)

- `playwright` (pinned): the verifier drives the real app and takes screenshots.
- `serena`: symbol-level code navigation (definitions, callers, references); the planner uses it when available. Needs `uv` (`brew install uv`).
- `github`: **read-only** (header `X-MCP-Readonly`), toolsets repos/issues/pull_requests/actions, to read PRs and CI failures. Needs `GITHUB_PERSONAL_ACCESS_TOKEN` in the shell environment (never in the repo). It stays read-only on purpose: agents never commit, push or merge.
